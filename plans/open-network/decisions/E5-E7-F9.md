# E5, E6, E7, F9: decisions

What shipped is described in `docs/TOR_NETWORK.md`; this records why, and what is open.

## The network file is the contract with the Tor network's builder

The first cut had a second file, `network.json`, parsed by `core/pkg/onionnet`. It was merged into
the ceremony's `tor-network.json`: one format, one parser (`tornet.ParseNetwork`/`Load`), with
`private` and `validator_onions` added to it and the fallback list dropped (a client bootstraps
from the authorities; nothing used the list). The file is strict (unknown fields, hostnames, IPv6
zones, bad ids are refused) because every field reaches a torrc. A file not marked private is
refused: the public network is not launched. `onionnet` now only runs a client tor on that file.
Validator onions are added after the ceremony by `orama global tor onions add`.

## E5 reporter

- Lives in `chain/reporter` and runs as `orama-global reporter`; it reads the authority's own
  votes (`*.vote`, by `dir-source` identity), not a bandwidth file directly: the vote's
  `Measured=` is the authority's bandwidth-file figure, and the advertised `Bandwidth=` is never
  read, so a relay cannot weigh itself.
- `consensus_weight` is the median measured bandwidth times `NoramaPerWeight` (1,000,000 norama
  per unit). x/relay does not rescale, so this constant fixes how Tor weight maps onto the
  100-ORAMA per-relay cap. It is a placeholder for G1 to sign.
- Epoch span: x/emission exposes only the start of the epoch in progress, so the reporter keeps
  the previous boundary in `state.json`. An epoch whose boundaries it did not see (reporter down
  across a close) is skipped with an error, not guessed.
- A reporter omits the relays of its own operator.
- x/relay takes a report for epoch `e` only during `e+1` and settles in the first block of `e+2`:
  the reporter drops an epoch past its window (`ErrWindowClosed`) or already settled
  (`ErrEpochSettled`) and does not retry it.
- The E0 vote and bandwidth-file fixtures do not exist yet; the test fixture
  (`chain/reporter/testdata/vote-sample.vote`) is written to the dir-spec by hand and should be
  replaced by a captured vote when E0 lands.

## E6 VPN client

Plan E6 is a Rust/arti/Tauri application in its own repository. This repository ships
`orama vpn up|check`, a proxy-mode client over unmodified upstream tor, as the network's first
client: it proves the network file, the bootstrap against the authorities and a rendezvous to a
validator onion service. A system-wide tunnel, DNS-leak and kill-switch tests at the TUN level
belong to the application.

## E7 launch gate

`vpnlaunch.Day` replaces `Snapshot`: thresholds must hold on each of the last 30 days, and the
heaviest-operator share is compared exactly (the old whole-percent field let 10.4% pass).
`LaunchEnabled` is false and pinned by a test. Nothing links the package into a binary.

## F9 onion submission

`--onion-network` runs a tor client on the network for one command and picks a validator onion
at random when none is given. Open: the validator onion list comes from the network file, not
from `x/nodes` endpoints; private sync (compact blocks over the network) is not done.
