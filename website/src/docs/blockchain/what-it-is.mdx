# What the chain is

Orama has a ledger. The binary is `oramad`. It is a Cosmos SDK 0.54 application on CometBFT 0.39, in its own Go module at `chain/`. The node software in `core/` does not import it. It only reads the chain's local RPC when it wants a height.

Application traffic does not go through this ledger. A database query, a deploy, a function call, and a wallet login still hit the gateway. The chain is a separate process with its own token, its own peers, and its own ports.

## What is wired

The stock modules are auth, bank, staking, slashing, distribution, consensus parameters, upgrade, genesis utilities, evidence, and feegrant. The Orama modules on top of them are:

- `x/emission` mints new coins, once per epoch.
- `x/fees` charges a base fee, burns it, and keeps earnings accounts.
- `x/token` creates factory tokens with fixed capabilities (pause, freeze, non-transferable, transfer fee).
- `x/power` decides the voting power CometBFT actually uses.
- `x/nodes` records operators, nodes, role bonds and service-key bindings.
- `x/storage`, `x/archive` and `x/relay` run storage deals, the history registry and relay rewards.
- `x/houses` is the governance module: two houses, proposals, votes and timelocks.
- `x/wasmpolicy` sets what contracts may do, and wasmd's `x/wasm` runs them. A binary built without cgo or with `-tags nowasm` does not link the contract VM and refuses to start a node whose genesis claims the wasm module.
- `x/cnft` and `x/market` hold compressed NFTs and the market that trades them.
- `x/shielded` is the shielded pool.

`x/staking` still holds bonds, delegations, unbonding, and jailing. It does not publish the validator set. `x/power` does.

## What is not wired

The SDK's `x/gov` is not wired. Governance is `x/houses`, and its rules are floors in code that no vote can lower. A vote can change the emission split between its recipients, schedule a software upgrade and a few other things the proposal types list, but it cannot change the emission schedule: the code treats that as a hard fork.

There is no IBC, no EVM, no group module, no authz, no `x/nft`, and no `x/circuit` or `x/crisis`. The stock mint module is not wired. `x/emission` replaces it. `x/inclusion` is a library the application calls from its block handlers, not a module.

The distribution module is wired, and its community tax defaults to zero, because the chain has no path that spends a community pool. Epoch rewards are not paid through that module. `x/power` pays them.

The module by module description is in the technical reference (`docs/whitepaper/technical-reference/vol2/39-chain-architecture.md`, "The module set").

## Addresses and the unit

Accounts use the `orama` prefix. A normal account looks like `orama1…`. A validator operator looks like `oramavaloper1…`.

The base unit is `norama`. One ORAMA is 1,000,000,000 norama. The bond denomination is `norama`. Key derivation currently uses BIP-44 coin type 118, the Cosmos default. The code marks that coin type as temporary.
