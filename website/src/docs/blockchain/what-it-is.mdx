# What the chain is

Orama has a ledger. The binary is `oramad`. It is a Cosmos SDK 0.54 application on CometBFT 0.39, in its own Go module at `chain/`. The node software in `core/` does not import it. It only reads the chain's local RPC when it wants a height.

Application traffic does not go through this ledger. A database query, a deploy, a function call, and a wallet login still hit the gateway. The chain is a separate process with its own token, its own peers, and its own ports.

## What is wired

Auth, bank, staking, slashing, distribution, consensus parameters, upgrade, genesis utilities, evidence, and feegrant. Three Orama modules sit on top of those:

- `x/emission` mints new coins, once per epoch.
- `x/fees` charges a base fee, burns it, and keeps earnings accounts.
- `x/power` decides the voting power CometBFT actually uses.

`x/staking` still holds bonds, delegations, unbonding, and jailing. It does not publish the validator set. `x/power` does.

## What is not wired

There is no governance module. Nothing on the chain can vote to change the emission table. The code treats that change as a hard fork.

There is no IBC, no EVM, no CosmWasm, no NFT module, no group module, and no authz. The stock mint module is not wired. `x/emission` replaces it.

Shielded transfers are not implemented. Fee comments refer to a shielding design. No module in this binary hides a transfer.

The distribution module is wired, and its community tax is set to zero, because there is no governance module that could spend a community pool. Epoch rewards are not paid through that module. `x/power` pays them.

## Addresses and the unit

Accounts use the `orama` prefix. A normal account looks like `orama1…`. A validator operator looks like `oramavaloper1…`.

The base unit is `norama`. One ORAMA is 1,000,000,000 norama. The bond denomination is `norama`. Key derivation currently uses BIP-44 coin type 118, the Cosmos default. The code marks that coin type as temporary.
