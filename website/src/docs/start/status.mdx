# What works today

This page is the honest inventory. It is written against the code on the `nightly` branch (network version 0.3.0). When a page elsewhere in these docs describes something not listed as live here, treat this page as the authority and report the mismatch.

## Services you can use

| Service | State | Notes |
|---|---|---|
| Static, Next.js, Node.js and Go hosting | Live | Five runtimes: `static`, `nextjs-static`, `nextjs`, `nodejs-backend`, `go-backend` |
| Namespace database (RQLite) | Live | Replicated across the namespace's three nodes |
| Per-app SQLite | Live | Backups to content storage |
| Cache (Olric) | Live | Distributed maps with TTLs |
| File storage (IPFS) | Live | Private swarm, pinned across the cluster. Quotas exist but are opt-in |
| Pub/sub and presence | Live | WebSocket and REST |
| Serverless functions | Live | WebAssembly, HTTP/WebSocket/pub-sub/cron triggers |
| HTTPS for deployments | Live | Under the cluster's own domain |
| Custom domains | Partial | Verified by TXT record. Certificates for custom domains are not issued, see [Domains](/docs/developer/domains) |
| Voice and video | Live | SFU plus TURN, relay-only by design |
| Stealth TURN | Live, optional per node | TURN over TLS on port 443, routed by server name |
| Push notifications | Live | Direct APNs, self-hosted ntfy, Expo |
| Anonymity proxy and tunnel | Live | Tor client on every node. Not a private Tor network, see [Privacy network](/docs/privacy/overview) |
| Relayed fetch | Live | Download a stored object without the storing node learning your address |
| Vault | Partial | Shamir-split secrets across guardian nodes. Do not use as the only copy of anything important |
| Sign-in with wallets, devices, scoped keys | Live | See [Sign-in](/docs/developer/sign-in) |
| Audit trail | Live | 90 days, `orama audit` |

## The chain

The chain is implemented and tested in the repository. It is not what `orama node install` starts, it is not on the request path of any app, and nothing about it has run on a public network.

| Part | State |
|---|---|
| ORAMA token, emission schedule, fees, voting power | Implemented |
| Staking, delegation, slashing | Implemented |
| Two-house governance (`x/houses`) | Implemented, gated closed at genesis |
| Storage deals with proofs | Implemented |
| Relay registry and reporting | Implemented. The epoch settlement that pays relays has no caller yet, so no relay is paid |
| Token factory | Implemented |
| Compressed NFTs and market | Implemented |
| Shielded pool | Implemented. A node accepts shielded bundles only when both verifiers are present |
| CosmWasm contracts | Implemented in builds with cgo. Five standard contracts in genesis |
| Block explorer | The page ships with seeded demo data. No live adapter yet |
| Public chain | Not built. Devnet, stagenet and localnet only |

Details are in the [Blockchain](/docs/blockchain/what-it-is) section.

## The privacy network

| Part | State |
|---|---|
| Tor client on every node, anonymity proxy, tunnel, `anon_fetch` | Live |
| Relayed fetch over Tor | Live (Node.js clients) |
| Submitting chain transactions to a validator over an onion address | Client side live. The server-side onion service is not installed by anything yet |
| A private Orama Tor network (directory authorities, relays, exits) | Not built. Only parameter validation and unit renderers exist, and exits refuse to start by design |
| VPN | Not built. `chain/x/vpnlaunch` is a launch-gate predicate with no users |

## Other things people ask about

- **Public sign-up.** Not open. Namespaces exist only on clusters whose operators allow them.
- **Open sign-in for end users.** A namespace can allow any wallet to sign in to it. See [Sign-in policy](/docs/developer/sign-in#sign-in-policy).
- **Mainnet.** There is none. The chain has not run on a public network.
