# WebRTC

Real-time voice, video and data channels for a namespace: a **TURN** relay and a **selective forwarding unit** (SFU) that forwards each participant's tracks to the others. It is opt-in per namespace.

## Architecture

```text
Client A                                   Client B
   | 1. Get TURN credentials (REST)           |
   | 2. Open the signalling WebSocket         |
   | 3. Exchange SDP and ICE through the SFU  |
   v                                          v
 +--------+     UDP relay      +--------+
 |  TURN  |<------------------>|  TURN  |
 | host 1 |   (public IPs)     | host 2 |
 +---+----+                    +---+----+
     | WireGuard                   | WireGuard
     v                             v
 +----------------------------------------+
 |        SFU servers (3 nodes)           |
 |  signalling on WireGuard only          |
 |  Pion WebRTC, RTP forwarding, rooms    |
 +----------------------------------------+
```

- **TURN-shielded.** The SFU binds only to WireGuard addresses. All client media flows through a TURN relay, and the server enforces `iceTransportPolicy: relay`, so there are no direct peer connections. Two people on a call never learn each other's IP addresses.
- **SFU on all three of the namespace's nodes, TURN on two of three** (redundancy without over-provisioning). If the namespace has fewer viable nodes than TURN needs, every viable node gets one.
- **One shared TURN server per host** (`orama-turn.service`) serves every namespace placed there, keeping TURN on the well-known ports 3478 and 5349 (restrictive networks routinely block other ports, and those are the networks whose users most need a relay). Isolation is the per-namespace HMAC secret: the credential carries the namespace, and the shared server resolves each to its own secret and rejects a namespace it does not serve.
- WebRTC needs the namespace on **three nodes**. A one-node evaluation cluster cannot enable it.

## Enable and disable

```bash
orama namespace enable webrtc --namespace myapp
orama namespace webrtc-status --namespace myapp
orama namespace disable webrtc --namespace myapp
orama namespace enable webrtc-stealth --namespace myapp     # TURN over TLS on port 443
```

**Enabling** generates the namespace's TURN secret (32 random bytes), records its config, allocates port blocks on each node, starts TURN on two nodes and the SFU on all three, asks each TURN host to apply its tenant set at once, and creates DNS records `turn.ns-<name>.<base>` (plain UDP and TCP TURN) and `turn-<name>.<base>` (a single-label host for TURNS). It fails if no TURN host confirms it serves the namespace, and rolls back everything it asked.

**Disabling** marks the config disabled first (so no reconciler restarts what is being stopped), tears down the SFU on every node at once, removes the namespace from each shared TURN server's list (TURN itself keeps running for other namespaces; it stops only when its last tenant leaves), frees the port allocations of units that are gone, deletes DNS records and database records. A node that cannot be reached keeps its allocation row so the next namespace is not handed the same ports; the failed teardown is recorded and replayed.

## Ports

| Service | Port range | Protocol | Reachable from |
|---|---|---|---|
| SFU signalling | 30000-30099 | TCP | WireGuard only (1 per namespace) |
| SFU media (RTP) | 20000-29999 | UDP | WireGuard only (500 per namespace) |
| TURN | 3478 | UDP and TCP | Public, shared per host |
| TURNS (TLS) | 5349 | TCP | Public, shared per host |
| TURN relay | 49152-65535 | UDP | Public, shared per host |
| Stealth TURNS | 443 | TCP | Public, when [stealth TURN](/docs/privacy/stealth-turn) is on |

SFU ports are never opened in the firewall. `webrtc_port_allocations` has unique indexes so two allocations on one node can never hold the same port.

## Authentication

Every WebRTC endpoint requires **a signed-in user's token**, not an API key, or a deployed app's own workload token:

```text
Authorization: Bearer <access token>
```

An API key on its own is refused, which is what makes a runtime key extracted from an app bundle worthless against it. The SDK gets the token by exchanging your key, or from `auth.verify()` after a wallet signs in. On the signalling WebSocket, where a browser cannot set a header, the token goes in `?jwt=` (never a key).

## Client integration

### 1. Get TURN credentials

```js
const res = await fetch("https://ns-myapp.cluster.example.com/v1/webrtc/turn/credentials", {
  method: "POST",
  headers: { Authorization: `Bearer ${accessToken}` },
});
const { uris, username, password, ttl } = await res.json();
// uris: turn:turn.ns-myapp.cluster.example.com:3478?transport=udp, ...tcp,
//       turns:turn-myapp.cluster.example.com:5349   (and the stealth host on :443 when enabled)
// username: "{expiry_unix}:{namespace}"   password: base64(HMAC-SHA1(secret, username))
// ttl: 86400 (24 h): a one-shot credential is not refreshed mid-call, so it must outlast any call
```

Plain TURN uses the two-label host `turn.ns-<ns>.<base>`; TURNS uses the **single-label** host `turn-<ns>.<base>`, because only a single-label host is covered by the `*.<base>` wildcard certificate, so only it validates in browsers.

### 2. Create the PeerConnection

```js
const pc = new RTCPeerConnection({
  iceServers: [{ urls: uris, username, credential: password }],
  iceTransportPolicy: "relay",   // also enforced by the SFU
});
```

### 3. Open the signalling WebSocket

```js
const ws = new WebSocket(
  `wss://ns-myapp.cluster.example.com/v1/webrtc/signal?room=${roomId}&jwt=${encodeURIComponent(accessToken)}`,
);
ws.onmessage = (event) => {
  const msg = JSON.parse(event.data);
  switch (msg.type) {
    case "offer": case "answer": case "ice-candidate": /* SDP and ICE exchange */ break;
    case "peer-joined": case "peer-left": /* update the roster */ break;
    case "turn-credentials": setTURN(msg); break;          // sent once, after welcome
    case "refresh-credentials": updateTURN(msg); break;    // at 80% of the credential TTL
    case "kicked": /* the SFU removed you; the socket closes */ break;
    case "server-draining": reconnect(); break;            // the SFU is shutting down
  }
};
```

`room` is optional but recommended. With it the gateway routes the upgrade straight to the room's SFU; without it the gateway reads your first (`join`) frame (at most 4096 bytes, within 5 seconds) and routes by its `roomId`. When both are present they must match, or the join is refused with `room_mismatch`. Room ids are 1 to 128 printable ASCII characters with no whitespace. Joins are limited to 60 a minute per signed-in identity, with a burst of 20 (429 with `Retry-After`).

The `userId` in a client's `join` frame is **ignored**: a client cannot say who it is. The identity in a room is the token's subject, and the device id (`did`) when the session is device-bound.

### 4. Rooms (REST)

```js
const headers = { Authorization: `Bearer ${accessToken}`, "Content-Type": "application/json" };
await fetch("/v1/webrtc/rooms", { method: "POST", headers, body: JSON.stringify({ room_id: "my-room" }) });
const rooms = await fetch("/v1/webrtc/rooms", { headers });
await fetch("/v1/webrtc/rooms?room_id=my-room", { method: "DELETE", headers });
```

Creating and closing rooms needs namespace ownership. `GET /v1/webrtc/rooms` reports the health of the SFU on the gateway's own node only.

## REST and signalling reference

| Method | Path | Auth | Description |
|---|---|---|---|
| POST | `/v1/webrtc/turn/credentials` | User token | TURN relay credentials |
| GET (WebSocket) | `/v1/webrtc/signal` | User token | Signalling |
| GET, PUT | `/v1/webrtc/config` | Owner or admin | `{"require_admission": bool}` |
| GET | `/v1/webrtc/rooms` | User token | List rooms |
| POST, DELETE | `/v1/webrtc/rooms` | Owner | Create, close |

| Message | Direction | Meaning |
|---|---|---|
| `join`, `leave` | client to SFU | Enter or leave a room |
| `offer`, `answer`, `ice-candidate` | both | SDP and ICE |
| `audio-state`, `video-state` | client to SFU | `{"enabled": bool}`: the client turned mic or camera on or off |
| `participant-state` | SFU to client | Another participant's state, or a mute the namespace applied (`"forced": true`) |
| `kicked` | SFU to client | You were removed (`data.code` is `removed` or `admission_expired`) |
| `peer-joined`, `peer-left` | SFU to client | Roster changes |
| `turn-credentials`, `refresh-credentials` | SFU to client | Credentials (`{username, password, ttl, uris}`) |
| `server-draining` | SFU to client | Reconnect |

**Negotiation: the SFU is the polite peer.** The SFU offers whenever it has something to tell a client; the client offers when it publishes; both can offer at once ("glare"). If a client `offer` arrives while the SFU's own is outstanding, the SFU withdraws its own, answers the client's, and offers again with everything the withdrawn offer carried. So the client treats it as perfect negotiation with itself impolite: ignore an SFU offer that arrives while your own is outstanding, and apply the SFU's next one after its `answer`. SFU m-lines have mids like `sfu1`, `sfu2`; do not assume numeric or contiguous mids.

**Signalling rate limit.** Offers and ICE candidates share one token bucket per peer (burst 40, refilled at 10 per second), and a peer may make the SFU yield to glare at most 6 times a minute. Exceeding either gets an `error` frame with code `rate_limited` and the socket is closed; the client can rejoin.

**Keyframes.** A subscriber that needs a keyframe sends PLI or FIR; the SFU relays at most one PLI per track per 500 ms to the publisher, so N subscribers cost one keyframe per interval.

**Failover.** If the cluster gateway cannot dial any of the namespace's gateways it answers 503 `NAMESPACE_GATEWAY_UNAVAILABLE` with `retryable: true`; reconnect with backoff. A peer ends exactly once whichever side ends it: the socket closing, `leave`, ICE failing, ICE not recovering within 15 s of `disconnected`, or a failed signalling write (5 s deadline).

## Room placement

A room lives in exactly one SFU process (rooms are in memory), so every peer of a call must reach the same SFU. Clients resolve the namespace host round-robin, so peers arrive at different gateways, and each gateway routes the socket to the room's owner:

1. List the namespace's SFU nodes still counted active in the registry.
2. Rank them by rendezvous (highest-random-weight) hash of `namespace|room|nodeID`: every gateway computes the same order.
3. Probe each in parallel with `GET /health?room=<id>` (1.5 s). An SFU that does not answer, or answers 503 (draining), is skipped; a healthy one reports whether it already hosts the room.
4. The owner is the first healthy node in rank that already hosts the room; with no live room, the top-ranked healthy node.

Nothing is written on the join path, so there is no lease to expire. A running call is never split by a recovery or by adding a node. With no SFU healthy the answer is 503; there is no fallback to the local SFU, which would split the call. A network partition between one gateway and the owner can split a room until the probe views agree.

## Identity, admission and moderation

The SFU takes every decision from a **join ticket** the namespace's gateway signs, never from a frame the client sends. The ticket carries the namespace, room, user, device, mute state, the gateway's event address, an issue time, an admission generation and an expiry 30 seconds out, under an HMAC key derived from the namespace's own TURN secret, so one namespace's SFU can neither accept another's ticket nor report into it. The SFU refuses an upgrade with no ticket, a bad MAC, an expired ticket or a ticket for another namespace (401 or 403). Keep node clocks synchronised: a gateway whose clock is more than 30 seconds behind the SFU's issues tickets the SFU finds already expired.

### Admission

By default every signed-in user with the `webrtc` grant may join any room. A namespace can instead require admission:

```bash
curl -X PUT https://ns-myapp.cluster.example.com/v1/webrtc/config \
  -H "Authorization: Bearer $ADMIN_TOKEN" -d '{"require_admission": true}'
```

With it on, a join succeeds only if the namespace's functions admitted that user to that room, and the admission is still good. A function admits with the `webrtc_admit` host function:

```text
webrtc_admit(room, user, device, ttl_seconds) -> {"room","user_id","device_id","expires_at"}
```

`device` empty admits from any device. `ttl_seconds` is 1 to 86,400. Admitting again extends the admission and lifts a revocation, and keeps a mute on record for 7 days after the admission expires. The admission's end holds for a live session: the SFU removes the peer then (`kicked` with code `admission_expired`; the leave event's reason is `expired`). Admitting again does not lengthen a session already open.

A join that is not admitted is refused before it reaches an SFU:

| Why | `?room=` upgrade (403) | Join frame without `?room=` |
|---|---|---|
| Never admitted | `WEBRTC_ADMISSION_REQUIRED` | `admission_required` |
| Admission expired | `WEBRTC_ADMISSION_EXPIRED` | `admission_expired` |
| Revoked by `webrtc_kick` | `WEBRTC_ADMISSION_REVOKED` | `admission_revoked` |
| Records cannot be read | `SERVICE_UNAVAILABLE` (503, retryable) | `admission_unavailable` |

Turning `require_admission` on or off changes **new joins** only. The policy (`webrtc_settings`) and admissions (`webrtc_admissions`) are tables in the namespace's own database (migrations 073 and 075), so they survive an SFU restart.

### Membership events

The SFU reports every join and leave to the namespace, which publishes it on the pub/sub topic **`_orama/webrtc/<room>`**:

```json
{"_orama":"webrtc.join","room":"standup","user_id":"0xabc…","device_id":"<did or absent>","peer_id":"<uuid>","at":"2026-10-06T10:00:00.123Z"}
{"_orama":"webrtc.leave","room":"standup","user_id":"0xabc…","peer_id":"<uuid>","reason":"left","at":"…"}
```

`reason` is `left`, `kicked`, `expired` or `closed`. The `_orama` key is the platform's: publish routes refuse a payload carrying it, so a subscriber that sees it knows the platform wrote the message. The whole `_orama/` prefix is reserved ([Access control](/docs/developer/access-control#reserved-pubsub-topics)); delivery is at most once, and a subscriber resynchronises from the `participants` list of a `welcome`.

### Kick and mute

Two host functions act on a participant:

- `webrtc_kick(room, user)` **revokes** every admission of `user` to `room` and removes their connections (`kicked`, then a `leave` event with reason `kicked`). Rejoining is refused until a function admits them again. Each admission takes the next *generation* of its user in its room, the join ticket carries it, and the kick carries the newest generation it revoked; the SFU refuses a ticket whose generation is not newer than the kick's, with no clock involved, so a user re-admitted right after a kick joins at once. Without `require_admission` there is no admission to revoke: the kick closes the live connection and the user may rejoin.
- `webrtc_mute(room, user, muted)` makes the SFU stop forwarding `user`'s audio (checked per packet on the server, so a modified client that keeps sending is silent) and tells the room with a forced `participant-state`. It is recorded on the user's admissions so it survives a rejoin.

Both go to **every SFU of the namespace**, over the overlay, each request signed with a MAC that names the receiver and a nonce, so a captured request replays onto nothing. If an SFU cannot be reached the function fails and names it; the revocation is recorded and repeating is safe.

## TURN credentials

- Username `{expiry_unix}:{namespace}`; password `base64(HMAC-SHA1(shared secret, username))`.
- REST and host-function credentials live 24 hours.
- Credentials the SFU hands to clients use the namespace's `turn_credential_ttl` (default 600 s), and the SFU sends `refresh-credentials` at 80% of it. Update your ICE servers when you receive it.
- The SFU's own relay credential lasts 24 hours and is swapped at 80% (19.2 h) with an ICE restart, so a session never outlives its relay credential.
- TURNS presents the cluster's `*.<base>` wildcard certificate. A self-signed certificate is never served. If the wildcard is not exported yet, TURNS stays off and clients keep plain TURN on 3478.

## Security model

- Forced relay: clients cannot bypass TURN.
- Per-namespace TURN secret, port ranges and rooms.
- A logged-in user, not a key.
- Join tickets, not client claims.
- The SFU binds to WireGuard addresses only and is reachable only through the relay.
- `Permissions-Policy: camera=(self), microphone=(self)` on gateway responses.
- Known limit: TURN credentials are namespace-wide and cannot be revoked per user.

```bash
orama namespace webrtc-status --namespace myapp
orama monitor report                       # per-namespace sfu_up and turn_up

```

`turn_up` is true when the host's shared TURN server is running **and** lists the namespace as a tenant.

## Operator notes

- A reconciler on every node (60 s) keeps SFU and TURN roles matching `webrtc_port_allocations`: it prunes departed members, reallocates roles of nodes that are no longer viable (only with a strict majority of viable members, so a partitioned minority cannot reshape roles; a lone survivor after a mass outage does not self-elect), starts an SFU that should run, retires one that should not, and advertises a node's TURN DNS records only when it both holds the allocation and is actually serving. Stopping requires positive evidence.
- On a node restart the cluster state file restores TURN and SFU from the registry after the core services (RQLite, Olric, gateway). If the registry is unavailable they are skipped with a warning and restored on the next success.
- Replacing a node moves its roles; see [Replace a node](/docs/operator/node-replacement).
